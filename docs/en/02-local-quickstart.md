# 2. Local Quickstart

## Prerequisites

Use macOS or Linux with:

- Node.js 22 or later
- Docker, Podman, or nerdctl
- `kind`
- `kubectl`
- A GitHub Copilot seat, Azure AI Foundry deployment, or GitHub Models token

Check the tools:

```bash
node --version
docker version
kind version
kubectl version --client
```

## Install the CLI

```bash
npm install --global @kars-runtime/cli
kars --version
```

For reproducible labs, pass a release explicitly:

```bash
kars dev --release v0.1.25 --target local-k8s
```

This command creates a kind cluster, installs KARS, and starts a development
agent. Follow the authentication prompt for the inference provider you choose.

## Inspect the environment

```bash
kubectl get pods -n kars-system
kars list
kars status dev-agent
kars inspect dev-agent
```

Look for a ready sandbox and separate agent/router containers. If a pod is not
ready, inspect Kubernetes events and router logs:

```bash
kubectl describe pod -n kars-system <pod-name>
kars logs dev-agent --service router
```

## Connect to the agent

```bash
kars connect dev-agent
```

Try a harmless prompt such as:

```text
Explain which component controls your network access.
```

The response is generated by the chosen model, but the request travels through
the sandbox router.

## Stop the lab

```bash
kars dev down
```

Use Docker mode only when you need a faster smoke test:

```bash
kars dev --release v0.1.25
```

Do not interpret Docker mode as evidence that production isolation or
NetworkPolicy works.

## Troubleshooting

| Symptom | First check |
| --- | --- |
| `kars` not found | Global npm binary is on `PATH` |
| Cluster creation fails | Container engine is running |
| Sandbox remains pending | `kubectl describe pod` events |
| Inference returns 401/403 | Provider login, endpoint, deployment, or token |
| Command flag differs | `kars <command> --help` and installed version |

## Exercise

Start the local Kubernetes environment, save the output of `kars inspect
dev-agent`, connect once, then tear the environment down. Identify the agent
container, router container, and NetworkPolicy before cleanup.
